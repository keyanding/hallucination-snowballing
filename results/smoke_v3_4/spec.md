# Experiment v3.4 Codex Specification
## Traceable Natural-Error Propagation in a Controlled Candidate Universe

## 0. Purpose

v3.3 successfully validated the branching machinery but failed to measure Natural Propagation Rate (NPR) because none of the naturally generated wrong first-hop entities had an explicit downstream mapping available in the frozen evidence.

v3.4 should solve that specific bottleneck.

The main research question is:

> When an LLM naturally selects the wrong intermediate entity during a multi-step task, does the downstream answer follow the wrong entity's known relation target?

The key design requirement is:

> Natural errors must remain naturally generated, but the error space must be traceable.

Therefore v3.4 should use a **controlled candidate universe** in which every plausible first-hop candidate has a known downstream mapping.

This experiment should prioritize direct measurement of natural error propagation before reintroducing the richer context-support manipulations from v3.1–v3.3.

Do not yet integrate SHAR/HalluSE.
Do not yet change model family.
Do not yet add broad context ablations.

---

# 1. Core causal structure

For each task define a closed candidate set:

```text
B1, B2, ..., Bk
```

with exactly one gold first-hop entity:

```text
B
```

and several alternative candidates:

```text
B'1, B'2, ...
```

Each candidate must have an explicit downstream mapping:

\[
B_i \xrightarrow{r_2} C_i
\]

The task asks the model to identify the first-hop entity from the candidate universe.

If the model naturally selects:

\[
\hat B \neq B
\]

then the downstream target is already known:

\[
C_{\hat B}
\]

This makes the natural error immediately traceable.

---

# 2. Main scientific quantity

The primary quantity is:

\[
NPR = P(C_{\hat B} \mid \hat B \neq B)
\]

This is the central measurement of v3.4.

The experiment should also compare the natural wrong branch against a corrected counterfactual branch:

\[
\hat B \rightarrow ?
\]

versus:

\[
B \rightarrow ?
\]

under the same task prefix.

---

# 3. Task format

Use real entities and real relations where possible.

Each item should contain:

1. an original entity/task target `A`;
2. a first-hop relation `r1`;
3. a small candidate set of possible first-hop entities;
4. enough evidence to distinguish among those candidates;
5. an explicit downstream fact for every candidate under the same `r2`.

Example structure:

```text
Question:
Where was the director of Film X born?

Candidate directors:
- Person A
- Person B
- Person C
- Person D

Evidence:
- Film X was made by the same director as Film Y.
- Film Y was directed by Person B.

Downstream reference facts:
- Person A was born in City A.
- Person B was born in City B.
- Person C was born in City C.
- Person D was born in City D.
```

The model must first identify one candidate as the director.

The first-hop answer should be generated by the model, not supplied.

---

# 4. Candidate universe size

Use:

```text
4 candidates per case
```

for the initial smoke test.

Rationale:

- large enough to allow nontrivial wrong selections;
- small enough to keep downstream mappings interpretable;
- enables exact tracing of every first-hop error.

Each candidate must map to a unique downstream target whenever possible:

\[
C_i \neq C_j
\]

for all `i != j`.

If unique targets cannot be guaranteed, exclude the case.

---

# 5. Case construction strategy

Create:

```text
20 candidate cases
```

before inference.

Use a fixed seed and freeze the dataset before model execution.

Prefer relations:

```text
director -> place of birth
director -> place of death
director -> father
```

or equivalent two-hop relations with single-valued targets.

Avoid multi-valued downstream relations.

The first-hop candidate set should contain:

- 1 gold entity;
- 3 plausible alternatives.

Alternatives should be semantically plausible enough that the model may naturally choose them.

Do not use obviously random distractors.

Possible alternative sourcing:

- directors of similar-era films;
- directors from the same country/genre;
- entities previously confused by the model;
- donor entities from prior 2Wiki cases.

But candidate selection must be frozen before seeing v3.4 outputs.

---

# 6. Avoid trivial first-hop lookup

The first-hop evidence should not reduce the task to direct string matching.

Bad example:

```text
Film X was directed by Person B.
Which candidate directed Film X?
```

This would make first-hop accuracy too easy.

Instead use one of two designs.

## Design A — evidence composition

Provide multiple facts from which the first-hop relation must be resolved.

Example:

```text
Film X was made by the same director as Film Y.
Film Y was directed by Person B.
```

## Design B — candidate-description matching

Provide attributes that identify the correct candidate indirectly.

The exact construction should remain simple enough to inspect manually.

---

# 7. Phase A — Natural first-hop selection

Ask the model to solve only the first hop.

Example:

```text
Question:
Where was the director of Film X born?

First solve only the first step.

Candidate directors:
1. Person A
2. Person B
3. Person C
4. Person D

Based on the evidence above, who directed Film X?

Answer with only one candidate name.
```

Record:

```text
natural_B_hat
```

Classify:

```text
CORRECT_FIRST_HOP
TRACEABLE_WRONG_CANDIDATE
OUT_OF_SET_ENTITY
INVALID_OUTPUT
```

The primary natural-error analysis uses only:

```text
TRACEABLE_WRONG_CANDIDATE
```

Do not coerce out-of-set answers into the candidate set.

---

# 8. Natural-error eligibility

A first-hop error is eligible if:

1. `B_hat` exactly matches one of the registered candidates;
2. `B_hat != B`;
3. a frozen downstream fact exists for `B_hat -> C_hat`;
4. `C_hat != C`;
5. direct downstream lookup succeeds.

Because every registered candidate must have a frozen downstream mapping, eligibility should be high for in-set wrong answers.

---

# 9. Prefix checkpoint

After Phase A, save the exact rendered transcript:

```text
original question
candidate list
first-hop evidence
model's first-hop answer
```

This is the natural checkpoint.

All downstream branches should replay this exact checkpoint.

Do not regenerate the first hop.

---

# 10. Core downstream branches

For every valid case run:

## N0 — Natural continuation

Use the exact natural checkpoint.

Ask only the second-hop question.

If `B_hat` is wrong and the output equals `C_hat`, label:

```text
NATURAL_PROPAGATE
```

If output equals `C`, label:

```text
NATURAL_RECOVER_TO_GOLD
```

If output equals another registered candidate target, label:

```text
NATURAL_OTHER_CANDIDATE_TARGET
```

If output is unsupported, label:

```text
NATURAL_OUT_OF_UNIVERSE
```

---

## C0 — Corrected counterfactual branch

Replay the same prefix, replacing only the first-hop answer with the gold `B`.

Then ask the same second-hop question.

Purpose:

```text
test whether correcting only the intermediate state redirects the downstream answer to C
```

---

## W0 — Registered wrong-state branch

For naturally correct first-hop cases, replace only the first-hop answer with one preregistered wrong candidate.

For naturally wrong first-hop cases, reuse `B_hat`.

Purpose:

```text
provide a matched counterfactual wrong-state branch for every case
```

---

# 11. Downstream reference facts

To avoid v2/v2.1 closed-book factual recall confounds, the second-hop prompt must explicitly contain the downstream mapping for all candidates.

Example:

```text
Reference facts:
- Person A was born in City A.
- Person B was born in City B.
- Person C was born in City C.
- Person D was born in City D.
```

These facts are identical across N0, C0 and W0.

This means the downstream stage measures state-conditioned selection, not parametric recall.

---

# 12. Direct lookup controls

For each case, verify all candidate mappings with direct lookup.

For each candidate `B_i` ask the relation-equivalent direct question.

Define:

\[
CLA_{all}
\]

over all candidate-target pairs.

Do not interpret NPR if downstream CLA is poor.

---

# 13. Primary metrics

## 13.1 In-Set First-Hop Accuracy — IFHA

\[
IFHA = P(\hat B = B)
\]

## 13.2 Traceable Natural Error Rate — TNER

\[
TNER = P(\hat B \neq B \land \hat B \in CandidateSet)
\]

## 13.3 Out-of-Set Error Rate — OSER

\[
OSER = P(\hat B \notin CandidateSet)
\]

## 13.4 Natural Propagation Rate — NPR

Among eligible traceable natural errors:

\[
NPR = P(output=C_{\hat B} \mid \hat B \neq B)
\]

This is the primary scientific endpoint.

## 13.5 Natural Recovery Rate — NRR

\[
NRR = P(output=C \mid \hat B \neq B)
\]

## 13.6 Counterfactual Correction Success — CCS

For naturally wrong cases:

\[
CCS = P(output=C \mid first-hop\ state\ replaced\ with\ B)
\]

## 13.7 Counterfactual Wrong-State Propagation — CWP

Across W0 branches:

\[
CWP = P(output=C' \mid wrong\ candidate\ state)
\]

## 13.8 Context Lookup Accuracy — CLA

Direct mapping accuracy for all candidate downstream facts.

---

# 14. Primary causal comparison

The most important within-case comparison is:

```text
same prefix
same downstream facts
same downstream question

Natural branch:
state = B_hat

Corrected branch:
state = B
```

If:

```text
B_hat != B
Natural output = C_hat
Corrected output = C
```

then label:

```text
STATE_CAUSAL_SWITCH
```

Count:

\[
SCS = P(STATE_CAUSAL_SWITCH \mid traceable\ natural\ error)
\]

---

# 15. Secondary context control

Include one stripped-context branch for eligible natural errors:

```text
S0:
downstream facts + state only
```

Compare with:

```text
N0:
natural prefix + downstream facts + state
```

Define:

\[
\Delta NPR_{prefix}
=
NPR(N0)-NPR(S0)
\]

Do not add E1/E2/E3-style support manipulations yet.

---

# 16. Sample progression

Use two stages.

## Stage 1 — smoke

Run:

```text
20 cases
```

Stop for inspection.

Desired outcome:

- at least 5 traceable natural errors;
- CLA >= 95%;
- low out-of-set error rate;
- valid N0/C0/W0 branch execution.

Do not force a minimum NPR.

## Stage 2 — pilot

Only if Stage 1 works.

Scale to:

```text
50–100 cases
```

Do not scale automatically.

---

# 17. Measurement gate

The smoke is interpretable if:

1. CLA >= 95%;
2. at least 15/20 cases have valid first-hop outputs;
3. at least 5 cases produce traceable natural errors;
4. OSER <= 25%;
5. invalid downstream outputs <= 10%;
6. branch replay is verified;
7. no candidate/output mappings are added after seeing model outputs.

Unlike v3.3, a minimum traceable natural-error yield **is required**, because v3.4 exists specifically to solve that bottleneck.

If fewer than 5 traceable natural errors occur, stop and redesign the candidate universe.

---

# 18. Stop conditions

Stop and inspect if:

- the first-hop task is too easy and produces almost no natural errors;
- the model frequently answers outside the candidate set;
- downstream candidate mappings are ambiguous;
- CLA drops;
- candidate targets collide;
- the first-hop evidence accidentally directly states the gold answer;
- branch replacement alters more than the first-hop answer span.

Do not rescue the run by swapping candidates after inference.

---

# 22. diagnosis.md

Answer explicitly:

1. Did the candidate-universe design increase traceable natural-error yield?
2. How often did the model select a wrong registered candidate?
3. What is NPR among traceable natural errors?
4. How often did natural errors recover to C instead?
5. When the first-hop state was corrected counterfactually, did the downstream answer switch to C?
6. Did stripped context versus natural prefix change propagation?
7. Were any results attributable to downstream lookup failure?
8. Did any cases leave the candidate universe?
9. Is the design suitable for a larger pilot?

---

# 23. What v3.4 can establish

If successful, v3.4 can directly support a statement like:

> When the model naturally selects a wrong intermediate candidate whose downstream relation is known, the downstream answer often follows that wrong state; correcting only the intermediate state changes the downstream trajectory.

This would be the first direct measurement of traceable natural error propagation in the project.

It would still be a constrained candidate-universe setting, not fully open-ended generation.

---

# 24. What comes after v3.4

Only after v3.4 successfully measures NPR should the richer context-support manipulations return.

The next experiment should ask:

> Given a naturally generated wrong intermediate state, how do gold-supporting, wrong-supporting, neutral and conflicting context alter propagation?

That would reconnect the direct natural-propagation measurement from v3.4 with the context-sensitive state competition discovered in v3.1–v3.3.

SHAR/HalluSE should remain outside the experiment until this natural propagation measurement is stable.
